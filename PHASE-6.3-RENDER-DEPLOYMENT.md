## 3. Render Service Configuration

Create a Render **Web Service** from the repository's `main` branch.

- Root directory: `backend`
- Runtime: Node
- Build command: `npm ci --include=dev && npm run build:mysql`
- Start command: `npm start` (or `node dist/server.js`)
- Health-check path: `/health/ready`
- Service type: Web Service
- Render supplies `PORT`; do not hardcode it in Render.
- The backend defaults `HOST` to `0.0.0.0`.

The readiness endpoint checks the database with `SELECT 1` and returns HTTP 503 when the database is unavailable. It does not perform expensive external-provider checks, so it is appropriate for the Render health check.

## 4. Required Environment Variable Names

Configure these in Render's Environment settings. Do not put values in source control or this document:

- `NODE_ENV=production`
- `DATABASE_URL` set to the existing Aiven MySQL connection string
- `JWT_SECRET` set to a strong production secret
- `CORS_ORIGIN` set to the exact trusted HTTPS web origin(s), comma-separated if needed
- `JWT_EXPIRES_IN` set to the chosen token policy, currently `7d` is the local example
- `NOVEL_GATEWAY_URL` only if a separate compatible novel service is enabled
- `CONSUMET_BASE_URL` only if an authorized self-hosted Consumet service is enabled
- `SCRAPER_BACKEND_URL` only if a trusted scraper backend is enabled
- `PROVIDER_REQUEST_TIMEOUT_MS` if overriding the bounded default
- `ASURA_BASE_URL`, `ASURA_TIMEOUT`, and `ASURA_RATE_LIMIT_MS` only if the limited Asura adapter is later enabled

Do not manually set `PORT` unless Render requires an override; the application reads Render's assigned port.

## 5. Aiven MySQL Architecture

```text
Render Web Service
        |
        | DATABASE_URL from Render secret environment
        v
Prisma MySQL Client generated by build:mysql
        |
        v
Existing Aiven MySQL schema
```

The Aiven schema was already migrated and verified in Phase 6.2B. No migration or reset is required for this deployment. If a future migration is added, use the isolated MySQL migration artifact and `prisma migrate deploy` only after review; do not use `db push` or reset commands.

## 6. Prisma Deployment Architecture

Local development continues to use:

```text
backend/prisma/schema.prisma -> SQLite
```

Render uses:

```text
backend/prisma/mysql/schema.prisma -> MySQL
```

The `build:mysql` script generates `@prisma/client` from the MySQL schema and then runs TypeScript compilation. The runtime command remains the existing `node dist/server.js`; no provider or content-gateway code changes are needed.
