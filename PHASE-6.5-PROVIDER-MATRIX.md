Verification date: 2026-09-17. Statuses distinguish local adapter success from Render deployment and physical-device UI verification. Enabled is not equivalent to working.

## WeebCentral — Backend — Limited (production verification pending)

- Domain: https://weebcentral.com (normal HTTP search verified).
- Previous: possible challenge/limited; current: search, details, full chapter lists, page lists and actual images PASS for One Piece and Solo Leveling.
- Actual adapter results: 1,193 chapters / 57 pages for the selected One Piece chapter; 201 chapters / 12 pages for Solo Leveling. Image requests returned HTTP 200 with image content types without added referer headers.
- Reader compatibility: existing normalized chapter/page contracts, through the shared backend bridge. Physical Android reader rendering pending.
- Strategy: HTML parsing in backend; page images load directly. Fixed upstream, bounded response size, timeout, per-origin serialization, cache and request deduplication. No arbitrary URL proxy.
- Discovery: not wired yet.
- Render: new adapter not yet deployed; frontend is opt-in and truthfully Limited until production verification.
- Reference: current site's HTML/HTMX request behavior; independently implemented.

## AnimeParadise — Direct — Limited (native rendering pending)

- Domain/API: https://animeparadise.moe and https://api.animeparadise.moe. Verified normal public REST search, details, 220 Naruto episodes, episode resolution, HLS master, variant and media segment HTTP 200.
- Actual media: ffprobe recognized H.264 video, AAC audio and ~1400.4 seconds duration. Segments use image-like filenames/content types; local ffprobe required permissive segment-extension parsing. No server-side access control was bypassed.
- Talos: direct adapter, existing normalized episodes/playback model, explicit HLS content type passed to expo-video for extensionless stream URLs. No Render dependency or user credentials required. Opt-in until physical phone playback is verified.
- Limitations: physical expo-video rendering unverified; external subtitles are not integrated. A real retrieved stream is not proof of Android playback. Some API connection attempts timed out; successful rerun recorded.
- Discovery: public recent episodes and popularity endpoints observed; not yet wired.
- Reference: public website client request contract. anime-sdk public documentation suggested this candidate; its GitHub tree API returned 404, so no source implementation was copied.

## MangaPill — Backend — Limited (Render/phone pending)

- Current domain: https://mangapill.com. Source itself states manhwa support was discontinued; only manga is advertised.
- Search/details/chapters/pages/image PASS for One Piece (1,209 chapters, selected chapter 57 pages) and Naruto (701 chapters, selected chapter 59 pages).
- CDN images/covers return 403 without source Referer and 200 with the normal source Referer. A source-specific fixed-host relay supports existing web/native image components; accepts only numeric CDN cover/page paths, rejects redirects and arbitrary URLs, and caps image size/time.
- Actual frontend bridge/gateway smoke PASS for normalized reader fields, cover/page image responses, and arbitrary-path rejection.
- Production relay and physical phone rendering remain unverified pending deployment/device testing. No unrestricted proxy or protection bypass.
- Discovery: native latest chapter feed exists, not wired yet.
